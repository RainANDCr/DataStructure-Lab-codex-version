# DataStruct Lab 2.0：审计之后的九阶段集成路线

本阶段（阶段 0）仅完成架构/功能审计、兼容与数据迁移设计，不开发下述业务功能。详细基线见 [项目审计](../architecture/PROJECT_AUDIT.md)、[功能清单](../architecture/FEATURE_INVENTORY.md)、[兼容计划](../architecture/COMPATIBILITY_PLAN.md)、[数据迁移计划](../architecture/DATA_MIGRATION_PLAN.md)。顺序按依赖和风险排列；每阶段完成后，先跑已有测试与构建，并验证旧 URL 和旧进度，再进入下一阶段。

| 阶段 | 集成目标与落点（建议） | 完成/准入条件 | 回退界限 |
| --- | --- | --- | --- |
| 1. 版本控制与基线防护 | 恢复 `.git` 或完整备份后初始化；识别用户改动，建立稳定基线和独立功能分支；为存储及入口补最少量回归测试 | 能显示真实工作区状态；Node 22 CI 与本机根目录测试、新版测试和构建一致；不丢用户文件 | 不合并新业务代码；保留原目录与数据备份 |
| 2. 扩展合同与开关 | 在 `web/src/compat/` 中定义新算法步骤/代码/路由适配合同；新增默认关闭的功能开关 | 旧 44 个课程、`/lab/compare` 和旧键的合同测试通过；旧播放器未替换 | 关开关即可恢复旧 UI |
| 3. 高级可视化基础 | 在 `web/src/features/advanced-viz/` 建增量轨迹模块、统一输入/错误边界和图形组件，不触碰旧引擎核心 | 至少一个独立算法可单步、暂停、回放并映射教学代码；既有步骤协议可消费 | 移除新导航或关开关，旧页保持原样 |
| 4. 高级算法专题 | 按需求优先级增加高级图/树/排序专题，逐个注册新 id；每个主题给出边界和反例 | 每个新增主题都有正确性与步骤回归测试、课程说明、深链接；现有 44 点不变 | 单个主题可独立隐藏/关闭 |
| 5. C/C++ 底层模型 | 在 `web/src/features/cpp-runtime/` 建明确的模拟内存、堆/栈、指针生命周期与调用帧模型，并标注“模拟”边界 | 最小示例对真实 C/C++ 输出与操作顺序有验证；内存错误示例不会误导为真实运行结果 | 独立于既有 `linkedVariants.ts`，关开关即可退出 |
| 6. 代码与动画对应 | 在新接口接可编辑/可运行样例或受控编译服务；按行号/执行事件映射新底层视图，旧只读教学片段继续工作 | 输入校验、运行隔离、超时/资源限制、编译错误可见；旧 C/C++/Python 标签不受影响 | 关闭执行入口，不影响旧课件与本地进度 |
| 7. 大学课程与 408 大纲 | 在 `web/src/features/study-408/` 建教材章节和 408 考点映射、先修关系及学习路径；旧 `catalog.ts` id 作稳定外键 | 每个新考点能链接已有/新增实验；旧目录和深链接仍能直达；未实现项明确标识 | 关闭新学习导航，旧九章目录保留 |
| 8. 练习与进度 | 加题目、判分、错题记录、学习分析；先完成版本化本地迁移，必要时再设计服务端存储 | 原始旧键保留；损坏/未知格式不覆写；刷新与多标签验证；迁移失败可回退并提示 | 关闭练习功能，保留旧键和新键供恢复 |
| 9. 集成验收与发布 | 做跨模块回归、无障碍、性能、移动端和部署检查；更新文档与课程验收记录 | Node 22 CI、单元/关键浏览器回归、生产构建、静态深链接、回退演练通过；无关依赖不升级 | 静态站点恢复上一版，用户数据不删除 |

优先级约束：阶段 5/6 的“真实 C/C++ 执行”不得靠现有教学片段冒充；阶段 8 的数据升级不得把对象直接写入 `datastruct-completed`。阶段 1 的 Git 阻塞解决之前，不应开展后续功能分支开发。
